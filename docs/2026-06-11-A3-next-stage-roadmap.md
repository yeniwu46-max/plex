# PLEX A3 下一阶段路线图

**基线日期**：2026-06-11  
**目标日期**：2026-06-30  
**目标**：满足并在可解释性、量化评测、工程可信度三个方向超越中国软件杯 A3 赛题要求。

## 一、当前结论

PLEX 已经具备赛题核心闭环，不再处于“补齐基本功能”的阶段：

- 七维动态画像支持对话抽取、置信度、证据、人工修改、历史版本和行为建议确认。
- 同一知识点可一次生成五类画像驱动资源，保存难度、时长、引用、画像快照、置信度和实际后端。
- 错题可触发画像建议，学生确认后更新画像、路径和推荐。
- 低置信度或校验异常资源进入教师审核，未批准资源不向学生发布。
- 学生、教师、管理员三角色链路可连续执行，后端 70 项测试和前端生产构建通过。

当前最大风险已经转变为：

1. **真实 AI 证据不足**：讯飞适配器和降级逻辑已实现，但真实联网调用尚未验收。
2. **真实多智能体验收未完成**：资源任务已具备六步显式契约、顺序数据传递和持久化轨迹，但尚缺真实讯飞调用形成的外部请求证据。
3. **效果证明不足**：有双画像差异案例，但没有系统化指标证明个性化优于统一内容。
4. **生产证据不足**：MySQL CI 已配置，但缺少可归档的 CI 运行结果、全新环境安装记录和并发性能数据。
5. **交付材料滞后**：README、技术总纲和早期答辩材料仍将部分已实现能力描述为规划状态。

## 三、超越赛题的四个差异点

### 1. 可审计的多智能体资源工厂

不只展示“六个智能体名称”，而是让每次资源任务形成完整审计轨迹：

- `profile_interpreter`：输出画像约束和个性化策略。
- `knowledge_retriever`：输出命中文档、章节和引用片段。
- `instructional_designer`：输出难度、教学顺序、案例和练习层次。
- `resource_generator`：生成五类结构化资源。
- `quality_reviewer`：输出 Schema、引用、安全、重复和代码语法检查。
- `path_planner`：输出资源在星轨中的位置和推荐理由。

轨迹必须保存智能体名称、输入摘要、输出摘要、耗时、模型后端、提示词版本、状态和失败原因。前端仅展示脱敏摘要。

### 2. 可量化的个性化优势

建立固定评测集，不以截图证明“看起来不同”：

- 两类固定画像：零基础生活化学习者、算法提升型学习者。
- 覆盖 16 个知识点，每个画像至少运行一次五资源生成。
- 指标包括任务成功率、结构通过率、引用有效率、画像约束覆盖率、资源差异度、平均延迟和降级率。
- 增加人工评分表：难度匹配、表达匹配、案例匹配、练习层次、推荐理由，各 1～5 分。
- 输出可直接进入 PPT 的 CSV、图表和结论。

### 3. 人机协同的教育安全

把教师审核从补救功能提升为产品特色：

- 低置信度、引用异常、超范围和结构异常自动阻断发布。
- 教师审核必须说明原因，保留审核人、时间和前后状态。
- 学生只看到已批准资源。
- 管理端展示风险类型分布、审核时长和降级后端占比。

### 4. 可恢复的现场演示

- 真实讯飞、规则降级、预生成审核资源三种模式均可演示。
- 断网、限流、错误密钥、任务中断和服务重启均有明确状态。
- 提交包不依赖开发者机器已有数据库或全局依赖。
- 演示脚本包含主路线、备用路线、截图和预生成数据。
