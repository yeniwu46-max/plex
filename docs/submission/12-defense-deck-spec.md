# PLEX A3 答辩 PPT 规格

正式答辩稿采用 16:9、10 页、7 分钟结构。每页必须包含一个明确结论和一个可核验证据对象，不使用虚构数据、Mock 冒充真实模型或未经核验的品牌素材。

## 1. 封面

**结论：** PLEX 是面向 Python 课程的可审计个性化学习闭环。

副标题：七维画像、六角色资源工厂、动态路径、教师审核、效果证据。

## 2. 问题与方案

**结论：** 统一内容无法同时适配零基础学生与算法提升型学生。

证据对象：同一 `loop` 知识点下两类画像的需求对照，以及 PLEX 的“画像 - 资源 - 行为 - 反馈”闭环。

## 3. 闭环架构

**结论：** 系统不是独立聊天框，而是贯穿三角色和数据库事实的教学系统。

证据对象：学生画像、资源生成、作答与错题、画像建议、动态路径、教师审核六阶段架构图；标出 Flask、Vue、SQLite/MySQL、RAG、Spark/本地规则边界。

## 4. 七维动态画像

**结论：** 画像具备来源、置信度、确认和版本历史，不是静态标签。

证据对象：七个维度及字段来源矩阵；展示接受建议后版本递增、拒绝建议后版本不变。

## 5. 六角色资源工厂

**结论：** 五类资源由可追踪的职责链生成并接受质量审核。

证据对象：画像理解、知识检索、教学设计、资源生成、质量审核、路径推荐六角色流程；标出引用、置信度、实际后端和审核状态。

## 6. 个性化差异证据

**结论：** 同一知识点因画像变化产生可量化差异。

证据对象：初学者与算法提升型学生在难度、表达、案例、练习层次和学习时长上的对照。使用 `personalization-evaluation.json`，不得人工编造资源差异。

## 7. 学习反馈与效果

**结论：** PLEX 能完成“错误 - 建议 - 确认 - 画像更新 - 路径变化”的闭环，并拒绝在样本不足时输出提升结论。

证据对象：三轮闭环结果，以及确定性前后测的 3 次错误到 3 次正确、正确率变化 `+100` 百分点、错题变化 `-3`。明确标注这是本地确定性场景证据。

## 8. 安全与人机协同

**结论：** 生成内容经过输入、检索、生成、发布四层控制。

证据对象：提示注入、超范围、敏感内容、错误引用、越权和恶意上传六类防护；教师审核决定学生可见性。安全专项当前 8/8 通过。

## 9. 工程可信度

**结论：** 项目具备可重复启动、零项目弃用、性能预算和候选包审计。

证据对象：

- 后端 `83 passed`，测试输出零告警。
- `Query.get()` 与 `datetime.utcnow()` 项目调用均为 0。
- 并发成功率和幂等率均为 100%，P95 173.79 ms。
- 首屏 111.9 KB gzip，最大懒加载 399.9 KB gzip。
- 候选文件逐项 SHA-256，密钥和本地环境排除。

## 10. 真实状态与演示收束

**结论：** 已验收、外部阻塞和未实现项严格分开，保证答辩可信。

证据对象：四象限状态表。

- 本地规则验收：画像、资源、闭环、效果、安全、性能、构建。
- 待真实验收：讯飞星火、GitHub 在线 CI、MySQL 8。
- 尚未实现：TTS。
- 最终冻结：清单匹配、提交 SHA 匹配、生成清单时工作树干净。

## 视觉规范

- 深蓝黑背景，青绿表示已通过，琥珀表示本地证据，红色仅表示阻塞。
- 图表数值必须来自 `backend/reports/` 或 `frontend/reports/`。
- 每页正文不超过 80 个汉字，技术标签可额外保留。
- 架构连接线必须有明确方向并连接到真实节点。
- 页脚标明证据文件和状态口径。
