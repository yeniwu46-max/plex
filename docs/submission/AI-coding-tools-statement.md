# AI Coding 工具使用说明

**项目**：A3 / PLEX 个性化学习系统  
**整理日期**：2026-07-20  
**用途**：初赛提交材料中“如若使用 AI Coding 工具，给出相关说明”的独立说明文档  

## 一、使用结论

本项目开发与材料整理过程中使用过 AI Coding 工具作为辅助工具，主要用于需求拆解、实现建议、代码解释、测试设计、运行错误定位、文档整理和提交材料口径校对。AI Coding 工具不是项目的自动开发主体，最终代码、数据、测试结论、演示口径和提交材料均由团队人工确认并承担责任。

## 二、工具类型与使用范围

| 工具类型 | 使用范围 | 输出处理方式 |
|---|---|---|
| AI 编程助手 | 辅助理解需求、梳理模块、生成候选实现思路、定位报错原因 | 由开发者审查后再决定是否采纳 |
| AI 文档助手 | 整理需求、设计说明、演示脚本、提交清单和答辩口径 | 与仓库文档、报告和运行结果交叉核对 |
| AI 代码审查/检查辅助 | 辅助发现接口不一致、边界条件、文档口径风险和测试缺口 | 不替代人工 review、自动化测试和真实运行验证 |
| 项目级规则/检查配置 | `.cursor/skills/`、`.continue/checks/` 等用于约束技术栈、API 形态和提交质量 | 作为协作约束，不作为功能验收结果 |

## 三、AI 辅助过的典型环节

1. **需求拆解**：把赛题要求拆分为学生端、教师端、管理端、多智能体、知识库、测试和提交材料等工作项。
2. **代码实现建议**：围绕 Flask API、Vue 页面、Pinia/Axios 数据流、JWT 权限、数据库模型和脚本验证给出候选实现方案。
3. **错误定位**：辅助分析启动失败、端口冲突、依赖缺失、接口字段不一致、构建失败和文档编码问题。
4. **测试设计**：辅助形成后端单测、接口回归、安全专项、性能恢复、知识库校验和发布就绪检查。
5. **文档整理**：辅助整理 `docs/submission/` 下的需求、系统设计、多智能体、测试、部署、演示脚本、冻结清单和本说明。

## 四、人工复核与质量控制

所有 AI 产出都必须经过以下复核流程：

- **代码层面**：由团队检查业务逻辑、接口契约、权限边界、异常处理和数据库兼容性。
- **测试层面**：通过自动化测试、前端构建、启动脚本、健康检查、知识库校验、安全校验和性能恢复报告验证。
- **文档层面**：所有指标和功能描述必须能回溯到代码、`backend/reports/`、运行接口或明确标记的外部验收记录。
- **演示层面**：视频和 PPT 不得把本地规则、Mock、静态截图或未接入外部服务表述为真实模型验收。

## 五、数据安全与隐私边界

使用 AI Coding 工具时遵守以下边界：

- 不向 AI 工具发送真实密钥、访问令牌、数据库密码、讯飞/大模型凭证或 `.env` 文件内容。
- 不提交包含真实学生隐私、个人身份信息或未脱敏学习记录的数据。
- 不把 AI 生成内容直接作为事实依据；事实依据必须来自仓库代码、可重复报告、测试输出或真实外部验收记录。
- 不使用 AI 生成未经核验的公司、用户、评测、性能或案例数据。
- 不把 AI 工具生成的建议绕过人工审查直接进入最终提交包。

## 六、与项目内智能体功能的区别

AI Coding 工具用于开发协作和材料整理，属于项目开发过程中的辅助工具；项目内“多智能体”功能属于 A3 / PLEX 系统自身的业务能力，用于画像理解、知识检索、教学设计、资源生成、质量审核和路径规划。两者边界如下：

| 对象 | 性质 | 是否面向最终用户 | 是否进入功能演示 |
|---|---|---|---|
| AI Coding 工具 | 开发辅助工具 | 否 | 不作为系统功能演示，只在提交材料中说明 |
| PLEX 多智能体流程 | 系统业务能力 | 是 | 可作为产品功能演示，但须标明实际后端 |

## 七、提交说明口径

建议在答辩或提交说明中使用以下表述：

> 本项目在开发过程中使用 AI Coding 工具辅助需求拆解、代码实现建议、测试设计和文档整理。AI 产出均经过人工审查、自动化测试、运行验证和演示复核；最终代码、数据、引用和功能表述由团队负责。开发过程中不向 AI 服务提交真实密钥、访问令牌或学生隐私数据。
