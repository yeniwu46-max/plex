# 项目需求分析说明

**文档编号**：PLEX-A3-REQ-01  
**版本日期**：2026-07-29（挑战赛优化版）

## 1. 文档目标与边界

本文档说明 PLEX 的需求来源、业务边界、用户角色、功能范围、非功能要求与验收口径，作为系统设计、测试用例、答辩材料和交付包核对的依据。

本项目按“本地可验收能力”和“外部环境待验证能力”分开说明。已经通过本地规则、离线降级或模拟数据验证的能力，不等同于真实第三方服务、在线 CI 或生产数据库的验收结果。

## 2. 新时代大学生学习需求 × 前沿 AI 结合点

### 2.1 学情背景：大学生学习方式正在变化

新时代大学生在计算机类课程中普遍呈现以下特征：

| 特征 | 表现 | 对教学系统的要求 |
| --- | --- | --- |
| 基础差异大 | 同班既有零基础也有自学过 Python 的学生 | 必须先建画像，再推资源，而不是统一进度 |
| 注意力碎片化 | 单次专注常在 15–40 分钟 | 需要短时、可中断、可续接的学习路径 |
| 偏好多模态 | 更习惯视频、图解、代码示例而非长文讲义 | 资源必须多模态，不能只有纯文本 |
| 即时反馈期待高 | 习惯 ChatGPT 式流式对话与 Markdown 排版 | 交互必须符合现代 AI 产品规范 |
| 希望“被理解” | 反感机械填表，更愿用自然语言描述自己 | 画像构建应走对话式，而非问卷 |

### 2.2 传统教学与通用 AI 工具的缺口

- **传统 LMS / 题库**：资源静态、路径固定，无法随学情动态调整。
- **通用大模型聊天**：能答疑，但缺少课程边界、知识库锚定、教师审核与效果闭环，易幻觉、易越界。
- **单一“AI 出题/AI 写讲义”插件**：只能生成一种形态内容，缺少多智能体分工与可追溯过程。

### 2.3 前沿 AI 与本项目的结合点

| 前沿能力 | 在 PLEX 中的落点 | 挑战赛相对初赛的增强 |
| --- | --- | --- |
| 大语言模型（DeepSeek / 讯飞星火） | 画像抽取、苏格拉底式答疑、教学资源包生成 | **SSE 流式输出**，对话体验对齐现代 AI 产品 |
| 多智能体协同（自研编排 + CrewAI/LangGraph 增强） | 画像解释→检索→设计→生成→审核→路径规划 | 前端 **智能体协作时间线** 可视化 |
| 语音合成 TTS | `audio_explanation` 语音讲解 | 文稿 → 可播放音频，含离线兜底 |
| 多模态视频生成（火山方舟 / SeeDance 类） | `video_lesson` 教学短视频 | 分镜脚本 + 视频卡片播放 |
| 文生图 | 驿站答疑“图解”卡片 | 文字流式回复 + 图解卡片 |
| Markdown / Mermaid / 代码高亮 | 全站 AI 输出渲染 | 真正渲染而非剥离星号 |

### 2.4 建设结论

PLEX 的目标不是“再做一个聊天机器人”，而是把前沿 AI 嵌进**可解释画像 → 多模态资源生产 → 教师审核 → 学习路径 → 效果证据**的教育业务闭环，服务一门完整的高校专业课程（《Python 程序设计基础》）。

## 3. 项目背景与业务问题

Python 程序设计课程面向的学习者基础差异较大：部分学生需要概念解释和低门槛示例，部分学生希望直接进入项目实践、算法拆解或调试训练。传统统一进度、统一材料、统一练习的教学方式，在以下方面存在明显不足：

| 问题域 | 现状表现 | 对教学交付的影响 |
| --- | --- | --- |
| 学情识别 | 学生基础、目标、表达偏好和学习节奏主要依赖教师经验判断 | 难以形成持续更新的学生画像，个性化教学缺少可追踪依据 |
| 内容供给 | 讲义、练习、拓展材料和代码任务通常分散维护 | 教师备课成本高，学生获取材料路径不稳定 |
| 学习路径 | 学生完成题目后的补救、拓展和复习路径缺少自动衔接 | 错题和薄弱点沉淀不足，重复犯错难以及时干预 |
| 资源审核 | 生成类资源存在置信度、引用来源和课程边界风险 | 教师需要可审核、可回退、可解释的资源发布机制 |
| 管理观测 | 任务成功率、风险状态、降级模式和外部依赖状态缺少统一视图 | 现场演示和交付验收时容易出现口径不一致 |

PLEX 的建设重点不是单纯生成学习材料，而是把“学生画像、课程知识库、资源生成、教师审核、学习路径、错题反馈、系统观测”组织成可运行、可审查的教学业务闭环。

## 4. 建设目标

### 4.1 业务目标

1. 建立面向 Python 初学者的个性化学习支持系统，覆盖学生自学、教师干预和管理员观测三个主要使用场景。
2. 支持基于自然语言对话的学生画像建模（≥6 维，本系统实现 8 维），并支持流式确认回复与实时刷新。
3. 以课程知识库为边界生成讲解文档、思维导图、分层练习、拓展阅读、代码实操，以及语音讲解、教学短视频等多模态资源。
4. 通过教师审核和低置信度标记控制资源发布质量，保留干预依据和审核记录。
5. 通过试炼、错题、推荐和学习路径更新，形成可追踪的学习改进链路。

### 4.2 工程目标

1. 前后端分离：Vue 3 + Vite + Naive UI + Pinia + Axios；Flask + SQLAlchemy + JWT。
2. 接口统一 `/api/v1`；对话类接口提供 SSE 流式端点。
3. 数据层兼容 SQLite / MySQL。
4. 支持本地离线演示、任务幂等、失败恢复和外部依赖降级。

## 5. 相关方与用户角色

| 角色 | 典型身份 | 核心诉求 | 关键能力 |
| --- | --- | --- | --- |
| 学生 | Python 课程学习者 | 获得适合自身基础和目标的多模态材料、练习路径和答疑 | 对话建画像、生成资源、试炼、错题、驿站答疑 |
| 教师 | 任课教师、助教 | 掌握班级学情，审核资源质量，针对薄弱点发布任务 | 班级概览、学生档案、资源审核、试炼发布 |
| 管理员 | 平台维护人员 | 观察任务状态、风险、后端降级和外部依赖 | 系统观测、任务成功率、风险分布 |

## 6. 核心功能需求（对照赛题）

| 赛题要求 | PLEX 实现 | 挑战赛增强 |
| --- | --- | --- |
| 对话式画像构建（≥6 维） | 8 维动态画像 + 对话抽取 + 版本历史 | 画像页挂路由；SSE 流式确认；右侧卡片实时刷新 |
| 多智能体协同生成（≥5 类资源） | 讲解/导图/题库/拓展/代码 + 资源包 | **语音讲解、教学短视频**；步骤时间线可视化 |
| 个性化路径规划与推送 | 知识图谱路径 + 推荐 + 三连错干预 | 保持并强化答辩口径 |
| 智能辅导（可选） | 驿站小E + 试炼辅导 | 流式 Markdown；按需图解卡片 |
| 学习效果评估（可选） | 多维报告 + 前后测证据 | 保持证据驱动口径 |
| 流式 / Markdown / 多模态卡片 | 初赛缺失 | **已补齐** |
| 防幻觉与内容安全 | 课程安全 + RAG 锚定 + 六步审核 | 保持 |

## 7. 非功能需求

1. **交互规范**：流式输出、Markdown 渲染（含代码高亮、KaTeX、Mermaid）、多模态内容卡片化。
2. **生成进度**：资源任务轮询 + 智能体协作时间线，避免长时间白屏。
3. **开源标注**：根 README 与配套文档显著位置列出开源组件名称、来源与协议。
4. **安全与准确**：提示注入拦截、敏感内容过滤、课程范围限制、引用校验。
5. **性能**：对话首 token 合理；多模态生成可异步/降级到脚本或文稿。

## 8. 验收口径

- 本地闭环：画像对话、资源生成（含语音兜底）、路径、试炼、审核、安全规则可在无外部密钥时演示。
- 外部增强：真实 DeepSeek / 星火流式、讯飞 TTS、火山方舟视频/图像在配置密钥后启用；未配置时明确降级，不虚报。

## 9. 限制与诚实边界

- CrewAI 为可选增强，主路径为自研顺序编排 + LangGraph 局部图；答辩表述为“自研编排 + CrewAI/LangGraph 增强”。
- 视频/图像生成依赖外部平台配额与网络；失败时保留分镜脚本或跳过图解，不影响主流程。
- 学习效果评估基于真实作答证据；证据不足时返回 `insufficient_evidence`，不伪造提升。
