# 中国软件杯 PLEX 赛题对照评估与冲刺计划

**项目名称**：PLEX Universe / A3 个性化学习系统  
**参赛课程**：《Python 程序设计基础》  
**评估日期**：2026-06-07  
**最终截止日期**：2026-06-30  
**团队可集中开发时间**：2026-06-22 至 2026-06-30  
**团队规模**：2 人并行

---

## 一、结论先行

PLEX 当前不是一个从零开始的概念原型，而是一个已经能够运行的三端教学平台。系统已有较完整的用户、班级、试炼、错题、评估、推荐和教师干预闭环，界面表现与游戏化设计也是明显优势。

但从中国软件杯本赛题的核心要求看，目前存在一个关键错位：

> 现有系统的强项是“教学管理、学习过程和游戏化体验”，而赛题的评分重点是“对话画像、多智能体个性化资源生成、动态路径与多模态推送”。

因此，剩余时间不应继续横向增加普通管理页面，而应集中补齐三项必选核心能力：

1. 对话式、可持续更新的 6 维以上学生画像。
2. 多智能体协作生成至少 5 类个性化学习资源。
3. 画像、学习评估、动态路径和多类型资源推送形成可演示闭环。

### 当前完成度估计

以下比例是基于当前仓库代码、测试和赛题要求得出的项目内部估计，不代表官方评分：

|---|---:|---|

## 五、尚未做到或证据不足的能力

### 5.1 对话式动态画像

当前能力雷达是根据试炼数据计算的 5 项技能指标，不能等同于赛题要求的学习画像。

至少需要新增以下 7 个画像维度：

1. 专业背景。
2. 知识基础。
3. 学习目标。
4. 认知或讲解偏好。
5. 易错模式。
6. 学习节奏。
7. 兴趣方向。

画像还必须支持：

- 自然语言对话抽取。
- 用户确认与修改。
- 学习行为触发更新。
- 保存每个维度的证据来源。
- 展示更新时间和历史变化。

### 5.2 五类个性化资源生成

当前系统存在资源记录和题目生成，但未形成符合赛题描述的资源生产线。

冲刺版本固定生成以下五类正式资源：

1. 专业课程讲解文档。
2. 知识点思维导图或知识图谱。
3. 分层练习题库。
4. 拓展阅读材料。
5. Python 代码实操案例。

额外生成：

6. 讯飞语音讲解。

每项资源必须包含：

- 目标学生画像摘要。
- 对应知识点。
- 难度和预计学习时间。
- 内容或资源地址。
- 生成智能体。
- 知识库引用。
- 置信度。
- 审核状态。

### 5.3 完整课程知识库

应提交一份真实可读、可检索、可复现的《Python 程序设计基础》知识库，而不是只展示 Mock 文件名。

建议最低覆盖：

| 模块 | 知识点 |
|---|---|
| Python 入门 | 程序结构、注释、变量与类型、输入输出 |
| 控制结构 | 运算与表达式、条件分支、for 循环、while/range |
| 数据组织 | 字符串、列表、元组/集合、字典 |
| 函数与实践 | 函数、异常处理、文件操作、简单算法 |

每个知识点至少包含：

- 概念讲解。
- 正反示例。
- 常见错误。
- 基础练习。
- 进阶练习。
- 来源信息。

### 5.4 防幻觉和内容安全

需要形成可展示的四层防护：

1. **输入层**：敏感词、违法违规请求和超课程范围识别。
2. **检索层**：只允许从课程知识库和白名单知识点获取事实。
3. **生成层**：要求结构化输出，校验知识点、字段和引用。
4. **发布层**：低置信度资源进入“教师待审核”，不能直接发布给班级。

### 5.5 生成体验与可观测性

需要新增：

- 生成任务状态：`pending`、`running`、`completed`、`failed`。
- 生成百分比和当前智能体步骤。
- 超时和失败原因。
- 重试入口。
- 降级后端标识，例如“讯飞星火”或“本地规则兜底”。

## 六、项目创新点

### 6.1 游戏化个性学习空间

PLEX 将编程学习转化为宇宙探索过程，通过星轨、试炼、补给站、碎片修复、等级、成就和班级排名降低初学者焦虑，增强持续学习动力。

### 6.2 教学闭环而非单一聊天机器人

系统围绕真实教学过程构建：

> 教师发布试炼 → 学生学习与作答 → 错题归因 → 薄弱点补救 → 学习评估 → 路径和资源调整 → 教师干预

这比仅提供通用 AI 对话更具有教学实用价值。

### 6.3 可解释的多智能体协作

将复杂的学习支持拆分为多个专业角色，并在前端展示各智能体状态、输入输出和耗时，使个性化建议具备可追踪、可解释的形成过程。

### 6.4 知识图谱、代码沙箱与错题联动

系统不仅生成文本，还将知识依赖、真实代码运行、测试用例、错题记录和路径推荐连接起来，适合 Python 实践型课程。

### 6.5 学生、教师双向智能化

学生获得个性化资源和路径，教师获得班级薄弱点、风险学生和干预建议，使 AI 不仅服务自主学习，也服务教学决策。

### 6.6 人机协同的资源质量控制

新增“置信度 + 引用来源 + 教师审核”机制后，可将防幻觉要求转化为产品能力，而不是只在文档中声明模型可能出错。

## 七、冲刺技术方案

### 7.1 学生画像

新增学生画像、画像版本或更新记录：

```text
student_profiles
- user_id
- major_background
- knowledge_foundation
- learning_goal
- explanation_preference
- mistake_pattern
- learning_pace
- interest_direction
- confidence
- evidence_json
- updated_at
```

建议接口：

```text
GET  /api/v1/student/profile
POST /api/v1/student/profile/chat
PUT  /api/v1/student/profile
GET  /api/v1/student/profile/history
```

`profile/chat` 接收学生自然语言，返回：

- 助手回复。
- 本轮抽取到的画像变化。
- 7 维完整画像。
- 待学生确认的低置信度字段。

### 7.2 多智能体资源生成

建议增加以下角色或将现有智能体扩展为对应职责：

1. 画像理解智能体：读取画像、当前进度和学习目标。
2. 知识检索智能体：检索课程知识库并输出引用。
3. 教学设计智能体：决定难度、顺序和表达方式。
4. 资源生成智能体：生成五类资源。
5. 质量审核智能体：检查事实、范围、敏感内容和引用。
6. 路径推荐智能体：将通过审核的资源编排进学习路径。

建议接口：

```text
POST /api/v1/student/resource-generation/tasks
GET  /api/v1/student/resource-generation/tasks/<task_id>
POST /api/v1/student/resource-generation/tasks/<task_id>/retry
GET  /api/v1/student/personalized-resources
```

生成任务返回：

```json
{
  "task_id": "rg_xxx",
  "status": "running",
  "progress": 40,
  "current_agent": "instructional_designer",
  "backend": "iflytek_spark",
  "resources": []
}
```

### 7.3 资源数据

扩展现有 `learning_resources`，或新增个性化资源表，至少保存：

- `user_id`
- `knowledge_key`
- `resource_type`
- `title`
- `content`
- `difficulty`
- `estimated_minutes`
- `profile_snapshot`
- `citations`
- `confidence`
- `review_status`
- `generator_agent`
- `generation_task_id`

### 7.4 讯飞与降级策略

模型后端优先顺序：

1. 科大讯飞星火。
2. 本地结构化规则生成。
3. 预生成的演示资源。

无论使用何种后端，前端必须展示实际后端，不能将规则或 Mock 结果包装为真实大模型生成。

讯飞能力建议：

- 星火大模型：画像抽取、讲解文档、阅读材料、题目和代码案例。
- 讯飞语音合成：生成语音讲解，作为多模态成果。

### 7.5 前端页面

在现有学生端中增加：

- 首次登录画像对话引导。
- 7 维画像卡片和更新时间。
- 个性化资源中心。
- 五类资源卡片及语音播放器。
- 智能体生成流程和进度。
- 引用、置信度和审核状态。
- “为什么推荐给我”解释。

避免新增孤立页面，应将资源入口接入：

- `/student/star-path`
- `/student/messenger`
- `/student/archives`

### 7.6 安全与质量

- 课程知识点白名单。
- 敏感词和违规意图过滤。
- JSON Schema 或等价结构校验。
- 引用不能为空的生成约束。
- 低于置信度阈值时标记待审核。
- 教师审核后才能发布为班级正式资源。
- 记录模型、提示词版本、生成耗时和失败原因。

## 十二、风险与应对

| 风险 | 影响 | 应对 |

## 十四、最终成功标准

到 2026 年 6 月 29 日晚，项目必须能够稳定演示以下完整链路：

> 学生通过对话建立 7 维画像 → 多智能体读取画像和课程知识库 → 生成五类个性化资源及语音讲解 → 资源进入个性化星轨路径并说明推荐原因 → 学生完成代码练习 → 系统记录错题并评估学习效果 → 画像、路径和资源推荐动态更新 → 教师查看评估结果并审核低置信度资源。

只要这条链路真实可运行、可解释、可复现，并配套完整文档和 7 分钟演示，PLEX 才能从“优秀的游戏化教学平台”转变为“真正对齐赛题要求的个性化资源学习多智能体系统”。
